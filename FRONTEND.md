# Frontend Sound Line

## Описание

Frontend музыкального сервиса Sound Line написан на React.

Он отвечает за интерфейс пользователя, отображение треков, загрузку музыки, воспроизведение аудио и работу с комнатами прослушивания.

## Используемые технологии

- React
- JavaScript
- JSX
- Vite
- CSS Modules
- Lucide React
- TanStack Query
- SignalR

## Основные компоненты

### App.jsx

Главный компонент приложения.

Отвечает за:

- переключение между страницами;
- подключение авторизации;
- управление очередью воспроизведения;
- отображение музыкального плеера.

### Sidebar.jsx

Боковое меню приложения.

Содержит переходы между основными разделами:

- Главная;
- Поиск;
- Загрузить трек;
- Моя медиатека;
- Комната прослушивания.

Также в боковом меню отображается информация об аккаунте и кнопка выхода.

### Home.jsx

Главная страница приложения.

Содержит:

- переходы к поиску, медиатеке и комнате прослушивания;
- недавно добавленные треки;
- недавно прослушанные треки.

### SearchPage.jsx

Страница поиска музыки и исполнителей.

Пользователь может найти трек, начать воспроизведение и перейти на страницу исполнителя.

### MyLibrary.jsx

Страница «Моя медиатека».

Содержит:

- плейлисты;
- загруженные пользователем треки;
- любимые треки;
- подписки на исполнителей;
- недавно прослушанные треки.

Пользователь может создавать и удалять плейлисты, а также добавлять и удалять треки внутри них.

### UploadTrack.jsx

Страница загрузки нового трека.

Пользователь выбирает аудиофайл, вводит название и имя исполнителя.

Frontend автоматически определяет длительность файла и отправляет данные на backend.

### Player.jsx

Музыкальный плеер.

Поддерживает:

- Play / Pause;
- перемотку;
- отображение времени;
- регулировку громкости;
- выключение звука;
- переход между треками;
- перемешивание и повтор очереди.

Плеер появляется после запуска трека.

### Rooms.jsx

Страница комнат прослушивания.

Пользователь может:

- создать закрытую комнату;
- присоединиться к комнате по коду приглашения;
- просматривать участников и очередь;
- добавлять треки в очередь;
- удалять добавленные им треки из очереди;
- выйти из комнаты.

Владелец комнаты управляет воспроизведением и может удалить любой ожидающий трек из очереди. При выходе владельца комната завершается.

## Авторизация

Для работы с приложением необходимо войти в аккаунт или зарегистрироваться.

После входа frontend сохраняет токен и использует его для запросов, требующих авторизации.

## Работа с backend

Frontend использует API для авторизации, работы с треками, любимыми треками, плейлистами и комнатами.

Основные запросы для работы с треками:

```http
GET /api/tracks
```

Получение списка треков.

```http
GET /api/tracks/mine
```

Получение треков, загруженных текущим пользователем.

```http
POST /api/tracks/upload
```

Загрузка нового трека.

```http
GET /api/tracks/{id}/audio
```

Получение аудио для воспроизведения.

## Загрузка трека

При загрузке:

1. Пользователь выбирает аудиофайл.
2. Frontend проверяет его формат.
3. Определяется длительность трека.
4. Пользователь вводит название и исполнителя.
5. Данные отправляются на backend.

Поддерживаемые форматы:

- MP3
- FLAC
- WAV
- M4A

## Воспроизведение

После нажатия на карточку трека:

1. Трек становится текущим.
2. Появляется музыкальный плеер.
3. Frontend получает аудио с backend.
4. Начинается воспроизведение.

## Совместное прослушивание

Для синхронизации комнаты используется SignalR.

После создания комнаты или входа по коду:

1. Frontend устанавливает соединение с сервером.
2. Пользователь подключается к комнате.
3. Участники получают обновления очереди и воспроизведения.
4. Владелец может запускать, останавливать и перематывать музыку для всех участников.

Участники могут регулировать громкость на своём устройстве.

## Хранение данных

Плейлисты, любимые треки и данные комнат получаются с backend.

Подписки на исполнителей и история недавно прослушанных треков сохраняются в браузере. Они не синхронизируются между устройствами.

## Запуск

Установка зависимостей:

```bash
npm install
```

Создайте в корне проекта файл `.env.local` и укажите адрес backend:

```env
BACKEND_URL=http://localhost:8080
```

Если backend работает по другому адресу, замените значение переменной.

Запуск проекта:

```bash
npm run dev
```

После запуска адрес сайта отображается в терминале. По умолчанию:

```text
http://localhost:5173
```

Проверка кода:

```bash
npm run lint
```

Сборка проекта:

```bash
npm run build
```
